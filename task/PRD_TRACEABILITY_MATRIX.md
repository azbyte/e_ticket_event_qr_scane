## Coverage / ownership audit

- Pemetaan meliputi requirement produktif §1–14 dan OPEN DECISION/technical gap §15, mencakup aktor, auth, event, category, form, brochure, staff, order, payment, fee, ticket, QR, check-in, attendee/export, Admin, email, responsive dan demo.
- Requirement C-01–C-03 tercatat sebagai owner keputusan produk, bukan developer yang boleh menebak. Gate tek/API di task memiliki owner domain, tetapi beberapa shared interfaces perlu amendment sebelum coding.
- Tidak semua requirement dapat dimiliki file per developer: `routes`, router, shared provider/client, schema dan database locked. Hal itu sengaja menjadi integrator/FINISHING/API contract dependency, bukan overlapping ownership.
- `backend/src/controllers/eventMetricsController.js` owner tunggal Tahap 2 adalah **D3** karena memuat Admin moderation dan event metrics. D2 mengonsumsi endpoint summary/sales frozen secara read-only. Lihat `TAHAP_2/FILE_OWNERSHIP.md`.
- `apps/lib/app_router.dart`/global route tidak memiliki D1–D3 owner dalam tahap terkait. G-04 deep link berhenti di interface request sampai maintainer menetapkan satu owner/amendment.

## Gate acceptance

Row hanya dapat dinaikkan ke TESTED setelah command/test dan hasil tercatat di laporan pada baseline yang sama. ACCEPTED memerlukan integrator menilai evidence dan requirement mapping. Source presence, audit snapshot, mock test, atau template kosong tidak mengubah status.
