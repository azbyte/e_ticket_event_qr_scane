LAPORAN ANALISIS DAN PENERAPAN TOOLS
====================================

Tanggal pemeriksaan: 2026-11-05
Proyek referensi: proyek pembanding yang dianalisis
Proyek target: management_ticket/e_ticket_event_qr_scane

1. RINGKASAN
------------
Referensi adalah workspace Flutter + NestJS/TypeScript yang terstruktur,
dengan delapan skills Markdown, instruksi agent, aturan kerja/domain/UI/quality,
CI, validasi kontrak dan dokumentasi. Target adalah aplikasi Flutter Android/Web
(Dart 3.13.2) dan backend Express 4 CommonJS/JavaScript dengan Supabase/PostgreSQL,
JWT serta role. Target sudah memiliki Flutter lints dan 5 widget tests, tetapi
sebelum audit belum memiliki test backend yang berfungsi (script npm test adalah
placeholder).

Tools dan panduan yang kompatibel diterapkan secara selektif. Tidak ada
dependency baru, perubahan schema/database/API/flow bisnis, atau konfigurasi
NestJS/MySQL dari referensi yang disalin.

2. INVENTARIS PROYEK REFERENSI
------------------------------
Pemindaian mencakup file project kecuali direktori build, Git internals dan
dependency vendor node_modules/. Daftar skill yang ditemukan:

1. Backend — pola API, transaksi, worker, data dan adapter.
2. Debug — reproduksi dan diagnosis masalah.
3. Flutter — implementasi alur aplikasi dan state.
4. Requirements — requirement, keputusan dan traceability.
5. Review — review berbasis risiko dan temuan.
6. UI — desain, ikon dan accessibility.
7. Verification — rencana tes, regresi dan batas bukti.
8. Workspace — struktur instruksi, skills dan dokumentasi kerja.

Lokasi skill sumber: skills/<nama>/SKILL.md; katalog root: SKILL.md.
Instruksi: AGENTS.md, CLAUDE.md dan aturan khusus assistant;
rules bersama: rules/{documentation,domain,portability,quality,research,ui,
workflow}.md. Skill berupa Markdown dengan metadata name/description;
instruksi AGENTS mengingatkan bahwa auto-discovery bergantung pada assistant.

Development/tooling yang teridentifikasi:
- Flutter/Dart dengan analysis_options.yaml/flutter_lints dan widget tests;
- NestJS, TypeScript, ESLint flat config, Prettier, pnpm workspace/lock;
- PostgreSQL/MySQL tooling, migrations dan Docker Compose (spesifik backend);
- Markdownlint, EditorConfig, OpenAPI lint Redocly, validator Python untuk link,
  kontrak, skill, PR policy dan release notes;
- GitHub Actions CI untuk validasi dokumen, kontrak, PR dan format; workflow
  release berbasis tag; PR/issue templates, security/contribution guidance;
- dokumentasi BRD/PRD/FRD/SRS, DESIGN, API OpenAPI, decision log, traceability,
  testing, git/workspace, versioning dan handoff;
- VS Code settings/extensions, .gitignore/.dockerignore, changelog dan license.

Tidak ditemukan bukti konfigurasi MCP server, custom subagent definitions,
Playwright/Cypress, visual regression, automated coverage, atau dependabot
sebagai workflow aktif. Aset visual/domain aplikasi referensi tidak digunakan
sebagai design system target.

- VS Code extension recommendations: tidak menambah extension yang belum
  dipastikan wajib/tersedia; EditorConfig bekerja lintas IDE.
- Changelog/release automation: belum ada proses release/tag target.

DITERAPKAN DARI SKILL REFERENSI:

  role, acceptance criteria, API dan batas prototype; disesuaikan ke PRD e-ticket.

  Karena paket tidak tersedia lokal, tidak ada konfigurasi ESLint/Prettier
  setengah jadi. Saat jaringan registry pulih, tambahkan versi kompatibel,
  konfigurasi flat ESLint untuk CommonJS, dan validasi existing source dahulu.

7. CARA MENGGUNAKAN
-------------------
AI assistant: buka root repository e_ticket_event_qr_scane. Baca AGENTS.md,
kemudian SKILL.md; pilih dan baca skill relevan. Assistant yang mendukung
AGENTS.md/skills dapat menggunakannya langsung. Bila IDE memakai format rules
lain, tambahkan instruksi secara manual; auto-discovery tidak dijamin lintas tool.

npm run format:check; npm run validate:skills.
Flutter: cd apps; flutter pub get; flutter analyze; flutter test.
GitHub Actions menjalankan checks tersebut pada push/PR. Workflow memerlukan
runner Ubuntu serta akses internet untuk SDK dan paket.
